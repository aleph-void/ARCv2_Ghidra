# Ghidra-Rare notes: ARCv2 (ARC EM/HS)

This is the Ghidra-Rare fork of [sony/ARCv2_Ghidra](https://github.com/sony/ARCv2_Ghidra)
(Roman Korkikian, Sony). Ghidra-Rare replaced the hand-written specification with a generated one,
tested it against GNU binutils, Ghidra's emulator and real ARC HS Linux binaries in both byte
orders, and fixed what the tests found. Authors, upstream commit and the list of changes are in
[CREDITS.md](CREDITS.md); the upstream limitations and their status are in [README.md](README.md).
It targets Ghidra 12.1.4 and also builds on 12.1.3 and 12.2.

## What it covers

| Language ID | Description |
|---|---|
| `ARCv2:LE:32:default` | ARCv2 (ARC EM, HS3x/HS4x), little-endian: 32-bit instructions and long immediates stored as two halfwords, high halfword first |
| `ARCv2:BE:32:default` | ARCv2, big-endian |

- **Instructions**: every instruction GNU objdump 2.45 decodes for `-M cpu=hs` and `cpu=em`
  (with and without the `dsp` class): the base set (16- and 32-bit), the MPY/DIV options, the
  ARCv2 DSP and SIMD extensions (`mac*`, `dmpy*`, `qmpy*`, `v*2h`, `v*4b`, `v*4h`, ...), the FPU
  (single and double precision), the FPX double-precision assist (`dmulh11`, ...), the QuarkSE
  extensions (`fmp_*`, `dsp_fp_*`), SecureShield `sjli`, atomics (`llock`/`scond`,
  `llockd`/`scondd`, `ex`), `enter_s`/`leave_s`, `ei_s`/`jli_s`/`ldi`/`bi`/`bih`. Where optional
  extensions share an encoding (major opcode 6), the HS FPU interpretation is decoded and the DSP
  one where the FPU has none.
- **Syntax**: objdump's (`ldh`/`sth`, `.di.aw`, `add.f.eq`, `bl.nj`, `0` for a discarded
  destination, register pairs `r4r5`, auxiliary register names for `lr`/`sr`/`aex`).
- **Semantics** (real p-code): every base operation with its flags; saturating arithmetic; `div`,
  `rem`; `xbfu`, `bmskn`, `set<cc>`, `norm`/`normh`/`ffs`/`fls`, `swap`/`swape`, byte and halfword
  shifts and rotates; 64-bit `mpyd`/`mpydu`, `ldd`/`std`, `llockd`/`scondd`; loads and stores in
  every address mode; branches, compare-and-branch, `bbit0`/`bbit1`, `dbnz`, calls and returns
  with and without delay slots; zero-overhead loops (`lp`, `lp<cc>`); `bi`/`bih` branch tables;
  `ldi`/`jli_s`/`sjli` through their base auxiliary registers; `enter_s`/`leave_s`, `push_s`/`pop_s`;
  `flag`, `lr`/`sr`/`aex`; FPU single and double precision add, subtract, multiply, divide, square
  root, fused multiply-add/subtract with the accumulator, compares (flags) and the conversions GCC
  uses. Everything else is a named pcodeop (see *Doesn't work*).
- **Spec files**: GCC calling convention (r0-r7, 64-bit values in r0:r1), DWARF register map, ELF
  opinion (e_machine 195), relocation handler and PLT markup, pspec with the auxiliary registers.

The specification is generated by `tools/gen_arcv2.py` (`data/languages/ARCv2_defs.sinc` and
`ARCv2_ops.sinc`); `ARCv2_insn.sinc` is hand-written. The operation tables in `tools/` are black-box
surveys of objdump's output made with the `tools/probe_*.py` scripts; no binutils or GCC source was
read. The ARCv2 Programmer's Reference Manual is distributed by Synopsys only after registration,
so it was not used.

## Testing

Requirements: Ghidra with this directory as `Ghidra/Processors/ARCv2`; `test/slotdis.c` built
against GNU binutils 2.45 (`--enable-targets=all`); an ARCv2 GNU assembler (binutils 2.45
`--target=arc-elf32`) for the emulator tests.

```
test/run-tests.sh [workdir]                 # generator, SLEIGH, decode diff, every-entry, emulator
test/fetch-real-samples.sh samples          # real binaries (pinned URLs and SHA-256)
REAL_SAMPLES=samples test/run-tests.sh      # ... plus the real-binary analysis
```

Environment: `GHIDRA_INSTALL_DIR`, `SLOTDIS` (or `BU_SRC` and `BU_LIB` to build it), `ARC_TOOLS`
(toolchain prefix, e.g. `.../bin/arc-elf32-`). `test/env.sh` gives the headless runs a private
settings directory.

## Results

### Decoding vs GNU objdump 2.45

`test/gen_corpus.py` writes three corpora in 8-byte slots (an instruction and room for a long
immediate) for each byte order; Ghidra (`DumpSlots.java`) and libopcodes (`slotdis`, `-m
arc:ARCv2` with `-M cpu=hs`, `cpu=em`, `cpu=hs,dsp`, `cpu=em,dsp`) decode the first instruction
of each slot and `test/compare.py` scores them. A slot agrees when Ghidra matches any of the four
option sets (ARCv2 cores are configurable).

| Corpus (each byte order) | Slots | Both decode | Exact | Semantic | Both reject | Explained | Unexplained |
|---|---|---|---|---|---|---|---|
| every 16-bit first halfword | 65,536 | 61,167 | 97.77% | 100% | 4,070 | 299 | 0 |
| every 32-bit high halfword x low 6 bits (bits 15..6 random) | 1,048,576 | 848,718 | 89.14% | 100% | 179,258 | 20,600 | 0 |
| random slots | 50,000 | 46,644 | 97.69% | 100% | 3,116 | 240 | 0 |

The little-endian and big-endian runs give identical counts. *Semantic* differences are spelling
only: objdump calls r61 `reserved`, and prints nothing for the unnamed extension conditions 16-20,
22 and 25-31, which Ghidra prints as `.e16` ... (so that the condition is visible).

Explained classes (all corpora, one byte order):

| Count | Class |
|---|---|
| 21,066 | odd register of a 64-bit pair (`ldd r3`, `std`, `vadd4h`, ...): objdump decodes it with "Warning: illegal use of double register pair", Ghidra rejects it |
| 17 | odd register in `llockd`/`scondd`: the same, but objdump prints no warning |
| 12 | `enter_s`/`leave_s` with register count 15 (reserved): objdump prints `[0xf]` |
| 28 | major 6, sub-opcodes 0x00/0x02 with F=1: objdump guesses between the DSP complex multiplies (`cmpyhnfr`/`cmpychnfr`) by operand form |
| 3 | `cbflyhf1r` in operand forms outside the two documented ones (objdump's guessed DSP class) |
| 3 | `vadd2` format 3 with a long-immediate b: objdump prints c as a pair (as one register otherwise) |
| 2 | objdump bug (below): `0,limm,u6` of sub-opcodes 0x20-0x2e of majors 5-7 |

Every-entry test (`CoverageCheck.java`, root patterns filled at random, then the patterns of
unreached subtable constructors overlaid on root patterns): **2,187/2,187 constructors reached** in
each language.

### Semantics (emulator)

`test/emu_tests.py` assembles 45 sequences with GNU as (`-mcpu=hs38_linux`, both byte orders) and
`EmuCheck.java` runs them in Ghidra's p-code emulator against hand-computed register, memory and
flag values: add/sub carries and overflow, adc/sbc, logic, min/max, bit operations, add1-3/sub3,
conditional execution, long immediates, shifts and rotates through carry, mpy/mpym/mpymu/mpyu/mpyw,
div/divu/rem/remu, saturating arithmetic, set<cc>, extensions and abs/neg, norm/ffs/fls/normh,
swap/swape/xbfu, loads and stores in every address mode (32-bit and 16-bit forms,
register-register, signed), ldd/std, push/pop, enter_s/leave_s, conditional branches,
compare-and-branch, bbit1, 16-bit branches, delay slots, calls with and without delay slots
(16- and 32-bit slot), jl to a long immediate, zero-overhead loop, dbnz, bi, llock/scond/ex,
flag/lr, FPU single and double precision arithmetic, square root, fused multiply-add/subtract,
compares, conversions, mpyd/mpydu. **45/45 pass in each byte order**; `run-tests.sh` also runs a
copy with one expectation made wrong and checks that it is reported.

GCC 15.3 (Bootlin arcle-hs38) was used as a black box to settle details: the `enter_s` frame
layout (its unwind tables: fp highest, then r13-rN, blink lowest, fp = sp), the `xbfu` operand
(`(x>>8)&7` is `xbfu r0,r0,72`: width-1 in bits 9..5, position in 4..0), `bmskn` (`x & ~3`),
`mpyd` results in r0 (low) and r1 (high), `fsmadd`/`fsmsub`/`fdmadd` with the addend in r58/r58:r59,
the conditions used after FPU compares (Z equal, C and N less, V unordered) and the conversion
codes of `fcvt32`/`fcvt32_64`/`fcvt64_32`/`fcvt64` (0 unsigned, 2 signed integer to float,
4 float to float, 9/11 float to unsigned/signed integer, truncating).

## Doesn't work

- **DSP, SIMD, complex-arithmetic, QuarkSE, FPX-assist and accumulator instructions are named
  pcodeops** (`mac*`, `dmpy*`, `dmac*`, `qmpy*`, `qmac*`, `cmpy*`, `cmac*`, `v*` SIMD,
  `vperm`, `valgn2h`, `getacc`/`setacc`/`normacc`/`flagacc`, `aslacc`, `sqrt`/`sqrtf`, `rndh`, `satf`,
  `abssh`/`negsh`, `dmulh*`/`daddh*`/`dsubh*`/`dexcl*`, `fmp_*`, `dsp_fp_*`, `bspush`/`bspeek`/
  `bspop`, `modif`/`modapp`, ...): p-code could express them, but their exact arithmetic (lane
  order, rounding, saturation, which accumulator half is written) is not established by any
  source usable here: the DSP databook and the PRM are not public, and objdump only names them.
- **FPU details**: `fcvt*` with conversion codes other than 0, 2, 4, 9 and 11 (rounding-mode
  conversions) are pcodeops; the fused multiply-add is modelled as multiply then add (two
  roundings); IEEE exception flags (FPU_STATUS) are not modelled.
- **Hardware and privileged instructions** are pcodeops with no register effect beyond what is
  architectural: `sleep`, `swi`/`swi_s`, `trap_s`, `brk`/`brk_s`, `unimp_s`, `rtie` (returns to an
  address held in hardware state), `kflag`, `seti`/`clri`, `wevt`/`wlfc`, `sync`/`dsync`/`dmb`,
  `prefetch*`/`prealloc`, `ei_s` (executes an instruction from the EI table), `nexttask`, `sflag`.
- **Ghidra core**: `SleighLanguage.parse` caches instruction prototypes by a 32-bit hash and returns
  a cached prototype when two different encodings hash alike, so Ghidra can show another
  instruction's prototype in rare cases (the decode harness found one such slot per byte order in
  the 32-bit corpus: `0x2cfb0fdc` `vsubadd4h.e28 r4,r4,pcl` shown as a cached `rsub.p`; the pairs
  depend on the build). `DumpSlots.java` therefore parses without the cache and lists the
  collisions it sees; none occurred in the real binaries (100% agreement with objdump). TLS relocations in shared objects
  (`R_ARC_TLS_TPOFF`/`DTPMOD`/`DTPOFF` in the GOT) need the runtime TLS layout and stay unapplied
  (error bookmarks); `R_ARC_COPY` is reported by Ghidra's ELF support as not supported; tail calls
  through a register (`j_s [r3]` after an epilogue) produce "Could not recover jumptable" warnings;
  12 libstdc++ functions with an empty C++ class parameter fail to decompile because the DWARF
  importer gives that parameter the same register as the next one ("Overlapping input varnodes");
  96 DWARF line-table entries of libstdc++ with negative line numbers are rejected by Ghidra's DWARF
  importer.
- The 3 bad-instruction bookmarks of the big-endian executables are calls to undefined weak
  symbols in GCC's crtstuff (`jlne 0`, `bl` to its own address), guarded at run time.

## Unverified

- The register-pair order (even register = low word) for 64-bit results is confirmed for
  little-endian (GCC's `mpyd`, `ldd`); for big-endian cores the same order is assumed.
- Zero-overhead loops follow the classic ARC model (decrement and branch back at LP_END); the
  behaviour of `lp` with lp_count 0 is not modelled.
- No freely licensed ARC EM firmware was found; EM-only encodings are covered by the decode
  corpora but not by real code. QuarkSE, FPX-assist and SecureShield instructions are decoded only.
- The aux register names come from objdump's tables; `lr`/`sr` read and write an AUX_REGS_BASE
  space without hardware side effects.

## Confirmed reference-tool bugs and quirks

- GNU objdump 2.45 decodes `0,limm,u6` (format 1, a = 62, b = long immediate) of sub-opcodes
  0x20-0x2e of majors 5-7 with the u6 printed as a register (`vadd4b 0,0x83e0d40e,r40`), while it
  rejects the format-0 `0,limm,c` form of the same instructions.
- objdump prints the c operand of `vadd2` format 3 as a register pair only when b is a long
  immediate, and warns about odd register pairs for `ldd`/`std`/SIMD but not for `llockd`/`scondd`.
- objdump omits the address-mode suffix of loads with a long-immediate base and offset 0, and of
  `ldd`/`prefetch*` with a long-immediate base; Ghidra prints what objdump prints.
